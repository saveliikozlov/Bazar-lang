WHAT I UNDERSTOOD
-----------------
Now bazar has implementations of loops with "крутимось поки / від.../по..." main keywords. Under the hood those are just transitions between instructions with different blocks of instructions depending on the loop type. Moreover,
the loops have pre-check to check the correctness of the condition, whether the it is realistic or not, is the range empty or not. The counter firstly is compared with the end before the increment, when it equals the end the loop
ends and increment does not happen, in case if we want firstly add then compare, it could appear as an error, for example for the integer overflow case. Furthermore the loops has the keyword "харе" that transit to the end of the
loop, it is mainly uses the stack logic, so we can go out of the loop in innermost loop properly. Our bazar language now has the optimization techniques. Semantic has the VarInfo objects, every declaration has one VarInfo and
each for each use reference to it. It is really important to have those object, because, for instance in comparison with just name referencing, we could get more irrelevant issues, it could be count as the reference inside the
inner scope of some logic even in case when it was not called, it would rubbish. About arithmetic, in some cases when user inputs something, we do not know what will be in the end, the output is unknown, it can end as the error,
so we cannot optimize such cases. We are deleting only literals, variable readings, constant_value operations, calls and ану кажи will never be deleted. Moreover, for better optimization, bazar has inlining which removes the
function calls and gives us more room for optimization, we have a simple check can_inline, which checks that the last line in the scope should be тримай and there are no others тримай in a function, this one is the easiest
solution the that тримай problem. Last but not least, our optimizer deletes unused functions if we cannot approach it from main. For better presentation of the loops and some minor optimization we have the bank application
that uses the loops under the hood and can be optimized with the respectful flag.
