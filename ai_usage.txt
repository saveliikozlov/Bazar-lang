2026-10-05 - Persistent failure counters and adaptive diagnostics
---------------------------------------------------------------
Implementation AI: Claude Opus 5.5, medium effort.
Review AI: OpenAI Codex, GPT-6.1-Sol, high reasoning effort.

Added diagnostics.py and integrated adaptive error messages into the
compiler and standalone lexer CLIs. Two persistent per-user values track
lifetime failures and the message counter. Each compilation failure adds
one to both. Above 10 on the message counter, an uncensored exclamation
precedes the original diagnostic and the message counter drops by two.
Above 40 lifetime failures, the specified final message replaces the body
of every compilation error and takes priority over the swear-word tier.

Stored both counters in SQLite with atomic transactions. Added a state-file
environment override and fallback to the original diagnostic when storage
is unavailable or invalid. Successful runs, usage errors and file errors
do not count. Library calls remain free of persistence side effects.

Updated README.md and LANGUAGE.md. Isolated counters in check.py and CLI
tests so automated validation cannot alter the user's personal state.
Added 11 regression tests covering boundaries, persistence, both CLIs,
UTF-8 output, invalid storage, library calls and concurrent failures.

Independent review and recorded results:
- 153/153 fixture checks passed; all frozen fixtures remained unchanged.
- 82 unit tests passed on the default Python and Python 3.9.6.
- Python syntax compilation passed for implementation and test modules.
- Direct CLI probes verified normal, swear-word and final-message tiers,
  exact byte positions, one stderr line, empty stdout and exit status 1.
- Twelve simultaneous failures against initially missing state were all
  counted, ending at lifetime 12 and message counter 10.
- The fixture runner passed outside the repository under an ASCII
  environment without changing a pre-existing personal counter.
- Original design notes, grammar, parser and AST files were unchanged.

Review outcome: PASS. No actionable defects were found, so no repair cycle

stage1-fixes, following the plan the user accepted:
